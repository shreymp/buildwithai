Tipoff: app map

A snapshot of how the code fits together, made from the finished v1.1 code (engine commit 78c4711, branch claude/gifted-hypatia-gz8ol7). The code may change after this, so search for the names below rather than relying on line numbers.

What the app does

You paste a recruiter’s message or a whole conversation. Tipoff checks it in your browser against plain rules written from the FTC’s descriptions of job scams. It tells you which scam script the conversation follows, which step you’re at, what the scammer will probably ask next, and what to do. Nothing is sent anywhere: there is no server, no AI model and no network request after the page loads.

There are three main pieces:

  • The check page (src/ui/): React components for the input box, the verdict, the script timeline, the highlighted messages and the evidence cards.
  • The engine (src/engine/): plain TypeScript with no browser code. It splits the paste into messages, normalizes the text, runs the rules and builds a report.
  • The rulebook (src/engine/rules.ts and playbooks.ts): rules and scam scripts stored as data. The “How it works” page displays this same data, so the explanation can’t drift from what runs.

To follow it yourself: run the app (see below), click the “Remote data entry offer” example, then open these places in your editor.

1

The click becomes a request: check in src/ui/CheckPage.tsx

Search for const check = useCallback. An empty box shows an inline error instead. Otherwise it calls runCheck(value, optionsFor(o)), where o holds the names you ticked as “you”. If a newer check started in the meantime, the older answer is ignored.

2

Off the main thread, safely: runCheck in src/lib/runCheck.ts

Sends the text to src/engine/engine.worker.ts so a huge paste can’t freeze the page. After 2 seconds (CHECK_TIMEOUT_MS) it gives up and the page shows a recoverable error. If the browser can’t start a worker, it runs analyze in the page instead.

3

The judgment: analyze and judgeMessages in src/engine/judge.ts

parseThread splits the paste into messages and decides which ones are yours. findInMessage runs every rule in RULES on a normalized copy of each of the other person’s messages, then maps matches back to the exact characters you pasted (toOriginal). verdictFor turns the findings into “Likely scam”, “Worth a closer look” or no match. pickPlaybook names the script. The resulting Report is what the components render.

The rule that decides “Likely scam” 
if ((strongAsk && (steps.size >= 2 || strong.length >= 2) && score >= 5) || (score >= 9 && steps.size >= 3)) verdict = 'likely';
else if (score >= 3 || strongAsk) verdict = 'closer_look';

A “strong ask” is a weight-3 rule at step 4 or 5 (money or identity). “Likely” needs it plus corroboration, so one scary phrase alone never gets the strongest label.

A practice to reuse

Write tests that could actually fail. Every engine test checked that each highlight’s quote equaled the text at its offsets. But the quote was made from those offsets, so that check could never fail. When the v1.1 Unicode change shifted every highlight after an emoji by one letter (“imple tasks”), all the tests still passed. The bug was caught only by looking at real output.

The fix was a check that uses outside knowledge: a highlight must never start or end in the middle of a word (cutsWord in tests/engine/helpers.ts, run on every sample and every adversarial case). It failed on the bug, and it immediately found a second one: amounts cut to “$2” instead of “$280”. The full story is in docs/phase3/round1.md, under “Found while fixing: highlight bugs”.

On any project: for each test, ask “what broken version of this code would still pass?” If the answer is “almost any”, check a property the result must have, rather than comparing the code’s output with itself.
